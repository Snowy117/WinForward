# F4 struct sizes and per-packet work counts — exact evidence

Tree: base `ca8d999` (+ Step 1 probes for the before column). Every size below is
`System.Runtime.CompilerServices.Unsafe.SizeOf<T>()`, asserted exactly by
`tests/WinForward.Core.Tests/FlowKeyShapeTests.StructSizesForDiagnostics` and printed by it
(`PacketLayout`'s 16 is asserted by `PacketLayoutTests.PacketLayoutFitsSixteenBytes`); every
count is asserted by `PacketPathWalkCountTests`.

## Header walks per redirected packet (exact)

Probe: `PacketPathProbe.ParseWalk` / `RevalidateWalk` / `ViewRewrite` (`[ThreadStatic]`, null in
production), driven through `CapturePacketProcessor.ProcessAsync` → `FlowDispatcher` →
`TcpProxyCoordinator` on one thread (`RedirectedForwardPacketWalksHeadersExactlyOnce`,
`RedirectedReversePacketWalksHeadersExactlyOnce`; thread id asserted unchanged).

| leg | before (red) | after |
|---|---|---|
| forward mid-flow, per packet | `ParseWalk` 3 + `RevalidateWalk` 1 = **4** | `ParseWalk` 1 + `RevalidateWalk` 0 + `ViewRewrite` 1 = **1 parse + 1 view rewrite** |
| reverse, per packet | `ParseWalk` 3 + `RevalidateWalk` 1 = **4** | `ParseWalk` 1 + `RevalidateWalk` 0 + `ViewRewrite` 1 |

The red split is quoted from the Step-1 run of the same harness (source line
`Assert.Equal(3 * count, parse.Count); Assert.Equal(count, revalidate.Count);` in
`PacketPathWalkCountTests`, flipped to `count / 0 / count` when Step 3 landed).

## Sequence-gate entries per redirected packet (exact)

The Step-1 instrument (`TcpRedirectAssociation.SequenceGateEntryProbe` +
`SequenceGateEntryCountForDiagnostics`, both deleted with `_sequenceGate` in Step 2) recorded **2**
entries for a forward+reverse packet pair (one per leg — the census's "two lock entries per
packet"); its fact `RedirectedPacketPairTakesTheSequenceGateTwice` (also deleted) asserted
`before + 1` after the forward drive and `before + 2` after the reverse drive.

After Step 2 the gate is deleted with the instrument, so `RedirectPacketTakesZeroSequenceGateEntries`
asserts the structural fact (`TcpRedirectAssociation` has no reference-typed instance field — a gate
cannot exist without one) on a drive that proves itself non-vacuous (both trackers advance).
`TcpRedirectAssociationHoldsNoLockField` pins the same structural fact directly.

## Defaulted-layout refusals (exact)

`PacketLayout` gates every consumer on `IsTcp` (a parsed layout whose transport is TCP), so a
`default(PacketLayout)` — the layout a packet that never parsed carries — is refused rather than
applied at the IP header's own offset. Red-before: 3 facts failed, the rewriter accepted the
defaulted layout and the real redirect leg staged the mis-rewritten frame for injection; one
allocation gate had been passing on exactly that behavior. Full text and commands:
`defaulted-layout-hardening.txt`.

| check | before | after |
|---|---|---|
| layout-driven rewrite with a defaulted layout | accepted (`true`), frame mutated at `14 + 12` | refused (`false`), frame byte-identical (`DefaultedLayoutIsRefusedByteIdenticallyRatherThanRewritten`) |
| sequence observation with a defaulted layout | observed a bogus value from offset 18 (`Actual: 0`) | tracker stays unobserved (`DefaultedLayoutObservesNoSequence`) |
| redirect forward leg with a defaulted layout | `Injected` (frame queued) | `Blocked` fail-closed, slot byte-identical (`RedirectLegRefusesADefaultedLayoutByteIdentically`) |
| dispatched flow packets carrying a parsed layout | not asserted | all valid (`EveryDispatchedFlowPacketCarriesAParsedLayout`) |
