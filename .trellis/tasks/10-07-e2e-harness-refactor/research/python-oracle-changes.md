# The Python reference's change list (E4-a)

`benchmarks/results/2026-10-06-e2e-competitors/analysis/analyze.py` is the **A side** of the
two-implementation oracle: the C# analyzer is judged by reproducing its output on the frozen
synthetic tree, byte for byte. That only means something if A itself is a *fixed* point, so this
document is the complete statement of what was allowed to move in it, and §5 is the list of things
that look like defects and must not move at all.

The whole change is reproducible mechanically. The transformation below was applied to the file at
`HEAD` and the result is what is committed — so "only field names changed" is a checkable claim, not
a promise:

```bash
python3 - <<'PY' > /tmp/analyze-after.py
import pathlib
RENAMES = (
    ("udpForeignConnection", "udp.foreignConnection"),
    ("udpArrived", "udp.arrived"),
    ("udpLossRate", "udp.lossRate"),
    ("udpSent", "udp.sent"),
    ("sentOk", "sent"),
)
NEUTRAL = (
    ('"generated_by": "benchmarks/results/2026-10-06-e2e-competitors/analysis/analyze.py",',
     '"generated_by": "e2e-analysis v1",'),
    ('"Generated by `analysis/analyze.py` from `%s`%s."',
     '"Generated by `e2e-analysis v1` from `%s`%s."'),
)
text = pathlib.Path("/tmp/analyze-head.py").read_text(encoding="utf-8")
for old, new in RENAMES + NEUTRAL:
    text = text.replace(old, new)
```

The diff against `HEAD` is **29 lines**: 27 field-name substitutions plus the two name
neutralizations. No line was added, deleted, reordered or re-indented, and no statement, condition,
default, format string or table layout moved with them.

## 1. Field names → their new spelling (27 occurrences, 5 names)

The rename table is `contract-rename.json` (`.trellis/tasks/10-07-e2e-harness-refactor/research/`),
whose rows the E1–E3 batches landed. Each substitution below is the *whole* rule for its name: it is
applied wherever the old spelling occurred, and the enumeration is what the guard against "silently
kept the old key" is made of.

|---|---|---|
| `sentOk` (dotted leaf: `tcp.sentOk`, `udp.sentOk`) | `sent` | `metrics/tcp.sentOk`, `metrics/udp.sentOk`, `metrics/latency/tcp.sentOk`, `metrics/latency/udp.sentOk` |

## 2. `generated_by` neutralized (1 line)

`analyze.py:5624` published its own repository path as `verdict.json`'s `generated_by`. It now reads
`"e2e-analysis v1"`. The reference's identity is not a fact about the campaign, and a line that names
one implementation makes the two implementations' outputs differ before any number is compared
(D6.4). This is the **first** of the two exceptions to "field names only".

## 3. `tables.md` line 3 neutralized (1 line)

`analyze.py:5332` wrote ``Generated by `analysis/analyze.py` from `<raw>`.``; it now writes
``Generated by `e2e-analysis v1` from `<raw>`.`` — the program name only. The `<raw>` value and the
rest of the sentence are untouched, and the line still carries the absolute path the oracle calls
both sides with. This is the **second** exception (D20.7 / A2-11).

## 4. The line that every batch of the port has to reproduce

The reference's own `plots/SKIPPED.md` (written when no plotting library is importable) is **not**
part of the oracle: `plots/` is outside both compared files, and the C# side writes its own fixed
text (`verification/plots-SKIPPED.md`) that deliberately does not name an interpreter. The
transformation above does not touch the plotting section at all.

## 5. Rendering quirks that must survive unchanged

Everything in this section looks wrong, is wrong, and is still the contract: the golden was frozen
from this behaviour, so the C# side has to reproduce it exactly. Each item names where it lives.

1. **§5's 154 eleven-cell lines against a ten-column header.** `md_table()` (line 403) joins whatever
   cells it is handed and never pads, aligns or truncates; `table_latency()` (line 3749) hands the
   percentile table eleven cells for a row whose histogram is missing or not carried — the row id, the
   arm, the count column, the eight percentile cells and the trailing `note` cell — while the header
   names ten columns. Measured on the frozen golden: 154 lines in §5 carry eleven cells, 108 of them
   inside tables whose header has ten. The port must reproduce both the cell count and the header, not
   repair either.
2. **The `|---|---|` separator row.** `md_table()` writes exactly `|` + `|---|---|…|` for the header's
   arity — no spaces, no alignment colons, no trailing spaces. The golden has 40 of them.
3. **An empty cell versus `n/a (<reason>)`.** A reading the harness wrote as JSON `null` (a rate
   whose denominator was zero) renders as an **empty cell**, never as `0` and never as `n/a`:
   `fmt_stat()` (line 355) returns `""` when every pass is null. Everything else that cannot be
   computed renders as `n/a (<reason>)` — 499 of those in the golden — or as a bare `n/a` where the
   reason is structural. The skeleton's clean tree has no all-null metric (see `FROZEN.md` §5), so
   this rule needs the C# side's own unit test; the rule itself is not up for discussion.
4. **`fmt_stat`'s three tails, and the shapes only two of them take here.** `(n=1)` for a single
   pass; `(n=K)` for K passes; and `(n=K of T; j null, m unavailable)` when some passes carry no
   value — the `j null` and `m unavailable` parts appearing only when non-zero, joined with `, `.
   The median form is `median [p25–p75]unit tail` with an **en dash** and the unit written *after*
   the bracket but *before* the tail when there is more than one pass
   (1085 such cells), and `median unit tail` when there is exactly one. The clean tree always has
   three passes per cell, so it exercises `(n=K)` and `(n=K of T; …)` (three cells of the second
   form: `(n=2 of 3; 1 unavailable)`) and never `(n=1)`; both rare forms are rules the C# side must
   implement and test rather than shapes it can copy from the golden.
5. **No thousands separators, no alignment, no padding.** `fmt_num()` (line 346) is `%.*f` — with
   the `%.3g` fallback described below — and the unit is appended: no grouping, no fixed width, no
   right-alignment, no truncation. `0` prints as `0.000` at three digits (27 cells in the golden),
   and a cell's rendered width therefore carries no information at all.
   The fallback is `%.3g` when the fixed form would print a *non-zero* value as zero: the golden has
   exactly two such renderings, `1e-06` and `8.000e-03` — a lower-case `e`, no `+`, and a two-digit
   exponent — against 27 literal `0.000` cells, so the two are not interchangeable.
6. **UTF-8 without a BOM, `\n` line endings, one trailing newline.** `tables.md` is
   `"\n".join(parts).rstrip() + "\n"` written with `Path.write_text(..., encoding="utf-8")`, and
   `verdict.json` is `json.dumps(..., indent=2, sort_keys=False) + "\n"` written the same way. The
   golden has no `\r`, no BOM, and ends in exactly one newline.
7. **`json.dumps`' indentation, order and escaping.** Two-space indent, `": "` between a key and its
   value, keys in insertion order (`sort_keys=False`), and `ensure_ascii=True`'s `\uXXXX` escapes for
   non-ASCII — the golden's `verdict.json` carries `\u2013` where `tables.md` carries the character
   itself, so escaping is per-file and must not be unified. `verdict.json` contains no `\u2014` only
   because the em dash appears in `tables.md`'s prose and not in any verdict string.
8. **§2 and §14 print absolute paths.** The ledger paths are printed verbatim, in discovery order
   (pass directory, then `--raw`, then `--raw`'s parent, with the four shipped names before the
   `*ledger*.jsonl` glob), which is why the oracle calls both sides with the same hardcoded
   `/tmp/wf-synth/raw` (§2's `Path` columns and `verdict.json`'s `raw` are compared text).
